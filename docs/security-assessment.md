# Pre-live Security Assessment
Status: offline release evidence only. This document does not grant production approval; the decision remains `NO_GO_PENDING_LIVE_EVIDENCE` until Azure live gates, pilot evidence, and explicit human approval exist.
Controls: pinned Actions, non-persistent checkout credentials, hash-locked dependencies, source/run-bound audit receipts, explicit container sources, non-root final users, location-only secret findings, and fail-closed remediation findings. The collector cannot accept risk; the hash-locked PyYAML parser rejects invalid, ambiguous, duplicate-key, recursive, oversized, custom-tag, or non-scalar workflows and remains outside the runtime image.
Commands: `python -m unittest discover -v -p "test_*.py"` runs the governed suite; `python scripts/collect_security_assessment.py --output runtime/staging-assurance/security-assessment-evidence.json` writes offline evidence. Exit `0` is offline PASS, `1` is valid `NO_GO`, and `2` is invalid evidence.
Release partition: `publish-staging-images.yml` owns a fixed `runtime_test_modules` array. `test_supply_chain_policy.py` asserts the exact list and rejects filesystem discovery; a reviewed PR must update both together.
Qualification partition: only `test_security_assessment`, `test_supply_chain_policy`, and `test_production_image_closure` run in the hash-locked `linux/amd64` overlay; only runtime and assurance images are published.
Evidence: CI retains the source-bound artifact with control outcomes, dependency receipt hashes, findings, owners, and the production decision even when a required control returns `NO_GO`.
Production boundary: offline success does not prove Entra role separation, Managed Identity, private networking, Service Bus/DLQ recovery, Blob immutability, PostgreSQL restore, alert resolution, restart idempotency, or digest-pinned rollback; live Azure gates, a limited pilot, and human GO remain mandatory.
